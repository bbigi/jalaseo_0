# 01.B — Page Speed Test Advanced (Next Steps “Pro Layer”)

> Scope: **Upgrade UX & insight** dari hasil PageSpeed Test yang sudah ada (mobile/desktop) **tanpa menambah metrik baru** dan **tanpa Health Score**. Semua berbasis data PSI run yang sudah tersimpan: `summary_text`, `insights`, `opportunities/audits`.

---

## 1) Goals

- Bikin hasil PageSpeed **lebih bisa diambil keputusan** (bukan cuma skor).
- User ngerti **apa yang harus dilakukan duluan** dan **kenapa**.
- Perbedaan **Mobile vs Desktop** kebaca jelas (bukan sekadar angka).
- Ada rasa “dashboard pro” tapi tetap ringkas.

---

## 2) Output utama per Run

### 2.1 Speed Summary (sudah ada)
- Label: **Excellent / Good / Needs Improvement**
- Reason singkat: 1–2 kalimat

**UI:** Card di paling atas tab (Mobile/Desktop).

---

### 2.2 Bottlenecks (sudah ada)
Urutan prioritas yang konsisten:
1. **LCP** → (loading)
2. **INP** → (responsiveness)
3. **CLS** → (stability)
4. **TTFB / JS** → (server & script)

**UI:** List 1–3 poin dengan badge “Critical / Major / Minor”.

---

### 2.3 Top 3 Recommendations (sudah ada)
Ambil dari Lighthouse opportunities dengan savings tertinggi.

**Setiap item tampilkan:**
- Title
- Savings (ms / KB)
- “Why it matters” (1 kalimat)
- “What to do” (1 kalimat, actionable)

**UI:** Table kecil / list cards.

---

## 3) NEW: Action Plan (Prioritized Fix Plan)

### 3.1 Konsep
Buat layer baru: **Action Plan** = rekomendasi yang sudah ada, tapi ditata menjadi “step-by-step” yang gampang dieksekusi.

### 3.2 Struktur data (di `insights.action_plan`)

- `items[]`:
  - `title`
  - `impact` = High/Medium/Low
  - `effort` = Low/Medium/High
  - `why`
  - `what_to_do`
  - `savings_ms` (nullable)
  - `savings_bytes` (nullable)
  - `related_metric` = LCP/INP/CLS/TTFB
  - `source_audit_key` (untuk trace)

### 3.3 Heuristik Impact/Effort (tanpa metrik baru)

**Impact** (rule of thumb):
- High jika:
  - savings_ms besar (mis. ≥ 300ms) **atau** savings_bytes besar (mis. ≥ 250KB)
  - audit terkait LCP/INP (images, render-blocking, JS)
- Medium jika savings menengah
- Low jika savings kecil

**Effort**:
- Low: cache policy, image format, compression, preconnect, lazyload
- Medium: reduce JS, remove unused CSS/JS, defer scripts
- High: server response (TTFB), heavy JS framework refactor, critical rendering path

> Ini bukan “kebenaran mutlak”, tapi cukup untuk MVP dan terasa pro.

### 3.4 UI
- Section baru: **“Action Plan (Recommended Order)”**
- 3–5 items, masing-masing punya badge Impact/Effort.
- CTA per item:
  - “Add to Fix Queue” (opsional nanti)
  - “Copy Checklist”

---

## 4) NEW: Mobile vs Desktop Comparison (lebih “berasa”)

### 4.1 Tujuan
Bukan cuma nunjukin “mobile lebih jelek”, tapi **kenapa beda**.

### 4.2 Output comparison (di `insights.comparison`)

- `winner_strategy`: mobile/desktop
- `delta`:
  - `performance_score_delta`
  - `lcp_delta`
  - `inp_delta`
  - `cls_delta`
- `top_reason[]`:
  - ringkasan: “Mobile lebih berat karena render-blocking JS + images”
- `reco_overlap`:
  - `same_recos[]` (audit yang muncul di keduanya)
  - `mobile_only[]`
  - `desktop_only[]`

### 4.3 UI
- Toggle “Compare Mobile vs Desktop” (muncul jika dua run ada)
- Tampilkan:
  - 3 delta utama (LCP/INP/CLS) + skor
  - alasan singkat (1–2 kalimat)
  - “Same fixes for both” vs “Mobile-only / Desktop-only”

---

## 5) NEW: Mini Trend (History Insight)

### 5.1 Syarat
Kalau `ane_pagespeed_runs` punya banyak data untuk website yang sama.

### 5.2 Output (di `insights.trend`)
- `last_n` (mis. 7)
- `score_series[]`: { created_at, score }
- `metric_series[]` optional: lcp/inp/cls snapshot
- `trend_label`: improving/stable/declining

### 5.3 UI
- Small sparkline / mini chart (simple)
- Copy: “Performance is improving (last 7 runs)”

> Ini bikin dashboard terasa hidup tanpa nambah API.

---

## 6) Empty / Edge Cases

### 6.1 Opportunities kosong
- Tampilkan message: “No major opportunities detected in Lighthouse output”
- Tetap tampilkan Bottlenecks + Summary.

### 6.2 Hanya satu strategy run
- Comparison disembunyikan
- CTA: “Run Desktop/Mobile to compare”

### 6.3 Skor bagus tapi UX buruk
- Tetap prioritaskan LCP/INP/CLS:
  - “Score looks fine, but INP indicates interaction lag.”

---

## 7) Engineering Notes (tanpa detail versi framework)

- Extend `PageSpeedInterpreter`:
  - build `action_plan`
  - build `comparison` (but only if both strategies exist)
  - build `trend` (optional)

- Storage:
  - simpan di `PageSpeedRun.insights` (json)
  - `summary_text` tetap sebagai string ringkas

- UI:
  - Tambahkan section “Action Plan” + “Comparison” + “Trend” di `speed-insights.blade`.

---

## 8) Acceptance Criteria

- Setelah run PageSpeed:
  - Summary + Bottlenecks + Top Recommendations muncul
  - Action Plan muncul dengan Impact/Effort + checklist
  - Jika mobile+desktop ada: Comparison muncul dan masuk akal
  - Jika ada history: Trend muncul
